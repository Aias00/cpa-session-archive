# MCP recall and shared text indexing

Status: implementation authorized by the user; in progress.

## Outcome

Let Codex and Claude invoke source-grounded recall via a read-only stdio MCP
bridge. Share exact repeated chunk text and lexical indexes while preserving
all request/message occurrences and citation semantics. Deploy verified changes
to the Apple M4 target and test both the protocol and real clients.

## Decisions

- Add the official MCP Go SDK, pinned to a compatible stable release; keep the
  existing collector language/runtime and use its authenticated HTTP APIs.
- Tools: `archive_search`, `archive_read_source`, `project_recap`,
  `archive_status`. Do not advertise curated memory that does not exist.
- Dedicated MCP read credentials, with server-side fixed project/session scopes
  or explicit owner-wide access. A scoped source read validates current source
  metadata, not caller-provided filters. Omit global corpus counts for scoped
  credentials. No raw upstream credentials enter MCP configuration or results.
- Bridge transports are stdio plus loopback HTTP through the existing SSH tunnel.
  No new remote unauthenticated listener; no hand-rolled MCP framing. Tokens come
  from private files and stdout contains MCP protocol messages only.
- Projection schema v3 stores text/FTS once per exact content hash, with separate
  occurrence rows per source/range/role. Scope and validity remain attached to
  each occurrence. Real repeated statements never become a single occurrence.
- Normalizer version remains v2; a storage-layout change must not reinterpret
  citations. Earlier derived projections rebuild from the retained archive.
- Prebuild the new projection on M4 before cutover, preserve old projection and
  verified raw backup, then atomically switch the collector with rollback ready.
